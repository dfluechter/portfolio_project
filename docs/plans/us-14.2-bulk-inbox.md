# Implementierungsplan: US 14.2 Bulk-Approve und Bulk-Reject für Inbox-Zertifikate

- **Epic:** 14 (Inbox-Automatisierung, Duplikatsprüfung & Batch-Processing)
- **Branch:** `feat/us-14.2-bulk-inbox`
- **Umsetzung:** Subagent-Driven Development (pro Task: Implementer → Spec-Review → Code-Quality-Review)

## Festgelegte Entscheidungen (vom User bestätigt)

1. **Alles oder nichts:** `bulk_approve` läuft in einem `transaction.atomic()`. Schlägt ein Item fehl, wird der gesamte Stapel zurückgerollt; alle im Lauf bereits gespeicherten Storage-Objekte (S3) werden kompensatorisch gelöscht. **Kein** `allow_partial`-Flag.
2. **Track-Pflicht (Epic 12):** Hat ein Item nach Auflösung von `track_ids` (Request) bzw. `suggested_tracks` (Fallback) keinen Track → `400 Bad Request` mit Meldung, die Dateiname und ID des Items nennt. Kein Ersatz-Track.
3. **Auswahl:** „Alle auswählen“ gilt nur für die aktuelle Seite (keine seitenübergreifende Aktion).
4. **i18n:** Texte des `PendingCertificateManager` werden zweisprachig (DE/EN) in `de.json`/`en.json` angelegt – nur diese Komponente.
5. **Batch-Limit:** max. 100 IDs pro Request. **Berechtigung:** nur Staff (`IsAdminUser`).

## IST-Zustand (Analyse Planer)

- `backend/portfolio/models.py`: `PendingCertificate` (Status `pending/approved/rejected`, M2M `suggested_tracks`, OneToOne `certificate`), `Certificate`, `Track`.
- `backend/portfolio/services/promotion.py`: `promote_pending_certificate()` / `reject_pending_certificate()` – Einzel-Promotion atomar mit Storage-Kompensation; keine Batch-Funktion, Track-Pflicht nicht validiert.
- `backend/portfolio/views.py`: `PendingCertificateViewSet.bulk_approve()` / `bulk_reject()` (`@action(detail=False)`), `_resolve_tracks()` – kein Batch-`atomic`, keine Request-Serializer, kein Limit, leere Tracks möglich.
- `backend/portfolio/admin.py`: `PendingCertificateAdmin.promote_selected()` / `reject_selected()`.
- `backend/portfolio/tests/test_pending_bulk_operations.py`: Grundtests vorhanden.
- Frontend: `frontend/src/components/dashboard/PendingCertificateManager.tsx` (Checkboxen, Bulk-Bar, Track-Picker „optional“, hartcodiertes Deutsch), `hooks/usePortfolio.ts` (`useBulkApprovePendingCertificates`, `useBulkRejectPendingCertificates`), `services/portfolioService.ts`, `types/index.ts` (`BulkApprovePayload`, …). Kein Komponententest vorhanden.

## Task 1: Backend – Request-Serializer, Batch-Limit, Track-Pflicht, atomarer Batch

**Dateien:** `backend/portfolio/serializers.py`, `backend/portfolio/views.py`, `backend/portfolio/services/promotion.py`, `backend/portfolio/tests/test_pending_bulk_operations.py`

**Anforderungen**
1. `BulkApproveRequestSerializer`: `ids` = ListField(IntegerField(min_value=1), allow_empty=False, max_length=100); `track_ids` = ListField(IntegerField(min_value=1), required=False, allow_empty=True). Unbekannte `track_ids` → 400.
2. `BulkRejectRequestSerializer`: `ids` wie oben.
3. Batch-Approve als Service-Funktion (z. B. `promote_pending_certificates_bulk`) in `services/promotion.py`: ein äußeres `transaction.atomic()`, Track-Pflicht vorab für alle Items prüfen, bei Fehler komplettes Rollback und Löschen aller im Lauf gespeicherten Storage-Dateien. Nur Items mit Status `pending` sind zulässig; nicht existierende/nicht-pending IDs → 400 (ganzer Batch abgelehnt).
4. `bulk_reject` atomar.
5. Views nutzen die Serializer (`is_valid(raise_exception=True)`) und `@extend_schema(request=...)`. Bestehendes Response-Format möglichst beibehalten, damit das Frontend kompatibel bleibt.
6. Quelldateien in `CERTIFICATES_PATH` werden niemals verändert/gelöscht – nur gelesen.

**Akzeptanzkriterien**
- Given 101 IDs, When POST `bulk_approve/`, Then 400 (max. 100).
- Given 3 IDs, deren dritte fehlschlägt, When `bulk_approve`, Then 400, keines `approved`, keine neuen `Certificate`, bereits gespeicherte Storage-Dateien gelöscht.
- Given Item ohne `suggested_tracks`, When `bulk_approve` ohne `track_ids`, Then 400, Meldung nennt Dateiname und ID.
- Given gültige Items + `track_ids`, When `bulk_approve`, Then alle `approved`, jedes Zertifikat hat genau die übergebenen Tracks.
- Given gültige IDs, When `bulk_reject`, Then alle `rejected`; bei ungültiger ID 400 und keine Änderung.
- Nicht-Staff → 403.

**TDD & Verifikation** (aus `backend/`): Tests zuerst; `.venv\Scripts\python -m pytest portfolio/tests/test_pending_bulk_operations.py -v`, danach `pytest --cov=portfolio --cov-fail-under=95`, `ruff check .`, `ruff format --check .`, `mypy .`.
